Azure ML (DP-100) Revision Guide

Super-dense cheat sheet focusing on Azure ML SDK v2, Compute, and MLOps.

1. Workspace and CLI/SDK v2 Core Concepts

  • SDK v2 philosophy: Declarative YAML configurations representing ML assets are processed by the `MLClient`.
  • Datastore vs Data Asset: Datastore holds the secure connection credentials to Azure Storage (Blob/ADLS). Data Asset is a versioned reference to specific files/folders inside a Datastore.
  • Command Job: The fundamental execution unit. Combines a script (`command`), a `compute` target, and a Docker `environment`.
  • Environment: Defines the OS (Docker image) and Python dependencies (conda.yml) ensuring code runs exactly the same everywhere.
  • Component: A reusable, self-contained modular step for a Pipeline, defining inputs and outputs.

2. Compute Limits and Security

  • Compute Instance: Cloud workstation. Usually single-user. Used for interactive notebook development.
  • Compute Cluster: Autoscaling, multi-node infrastructure. Used for heavy training jobs and distributed ML. Scales to 0 when idle.
  • Managed Identity: The best practice for security. Allows a Compute Cluster to authenticate to Key Vault or Storage without passwords in the code.
  • Key Vault & ACR: Key Vault holds secrets. ACR (Azure Container Registry) holds the Docker images used for training environments and deployed endpoints. Both are created automatically with the Workspace.
  • VNet Isolation: To prevent internet access, place the Workspace and Clusters in a secure Azure Virtual Network, accessing local on-prem data via VPN/ExpressRoute.

3. Automated ML and Hyperparameters (Sweep Jobs)

  • AutoML Data Guardrails: Automatically checks for class imbalance, missing features, and high cardinality before training begins.
  • Grid Sampling: Exhaustive search of all hyperparameter combinations.
  • Random Sampling: Randomly picks hyperparameters. Supports early termination to save costs.
  • Bayesian Sampling: Uses prior runs to pick better hyperparameters intelligently. Does NOT support early termination.
  • Bandit Policy: Early termination based on a slack factor/amount relative to the current best performing run.

4. Responsible AI and MLflow

  • MLflow: The tracking URI of the workspace directly accepts `mlflow.log_metric()` commands without specific Azure SDK code. Standard for MLOps tracking.
  • Fairlearn: Toolkit used to identify performance disparities across demographic cohorts (e.g., gender, age) and apply mitigation algorithms.
  • InterpretML (Feature Importance): Calculates global (overall model) and local (individual prediction) feature importance using techniques like SHAP.
  • Error Analysis: Visualizes data as an error tree or heatmap to quickly identify specific slices of the dataset where the model makes the most mistakes.

5. Deployment and Monitoring

  • Managed Online Endpoint: Fully managed REST endpoint. Handles SSL, authentication, and autoscaling natively.
  • Blue-Green Deployment: Used with Managed Endpoints. Route 10% of traffic to a newly deployed model to test it in production before 100% switchover.
  • score.py: The required scoring script. Must contain an `init()` function (runs once to load the `.pkl` model into RAM) and a `run()` function (runs on every API request).
  • Data Drift: Monitored over time. It occurs when live production data statistically differs from the baseline data used to train the model, requiring a retrain.
